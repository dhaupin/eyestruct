## [Unreleased]

### Added (2026-11-01, the version-truth census)

- `package.json` is the single version truth, and the living surfaces can no longer drift from it: a census leg derives the root version and refuses (a) a `web/package.json` version that moved in a different commit, (b) a README `Status: **X.Y.Z` line carrying a stale number. The only hand-synced truths were web's package.json and the README status line - both held by the leg now, so the release commit's always-move-them-together step is enforced, not remembered. Family ruling asked for: every sibling adopts the same shape (issue filed to the fam with this repo as the worked example).

### Fixed (2026-11-01, the walk-lap drift round)

- The MCP walk tool re-derived the candidate-name slug inline and was BLIND to the manifest's `slot:` override - the CLI and MCP lanes named the same routes differently, which is exactly the drift the one-reader rule (`walk.candidateName` is the only reader) exists to kill. ### Added (2026-11-01, the canvas-cap refusal)

- `RASTER_CANVAS` (the 30th reason code, exit 1) : an SVG can DECLARE an enormous render canvas (`width="200000"`), and a renderer handed those bytes allocates before it can complain - a committed bomb rides CI, since the raster:icon leg renders committed SVGs on every push, and an allocation failure previously surfaced as a LIE (`RASTER_BAD_XML`, a name that says the markup is wrong when the size is). The raster gate now parses the declared canvas (width/height with unit conversion, viewBox span when absent) and refuses over-cap declarations BY NAME at the input stage - before the renderer module loads, so the verdict is identical on machines with and without @resvg/resvg-js (the never-machine-dependent refusal doctrine). Caps: 12,000 px per dimension, 3.2M px area (~126 MB RGBA). The carrier case rides eye-adapter's refusal-grammar case first (the UNKNOWN_FLAG lane, same in-case receipt shape - no verdict-count move), the census moves 29 -> 30 codes, and the mirrors moved in the same change: docs/reasons.md table + freeze line, AGENTS.md, the discussions index, the web Home header. ### Fixed (2026-11-01, the walk round: transport + containment + funnel)

- The MCP stdio transport's newline buffer was unbounded: a client piping bytes without a newline (a frame bomb, malformed or hostile) grew the pending string until OOM - the newline-delimited contract never asked for that. The transport now carries a 1 MiB frame cap and refuses BEFORE accumulation: one named `-32700` reply ("send one newline-delimited request per line"), the transport stops reading, and the server closes at exit 1 - a refusal drop, not a silent drain. Battery leg pins the refusal over a real stdio spawn.
- The served-dist containment gate moved from statSync to lstatSync on the candidate ladder, plus a read-time lstat re-check: a symlink inside the served root used to escape and serve arbitrary host files (statSync followed the link; the decoded-path resolve-containment belt never saw it). A committed untrusted tree can no longer turn the loopback server into a file reader. Leg pins it with a symlinked escapee in a temp served tree.
- `gate`'s refusal enumerations are capped: DANGLING_ROW and UNRECORDED now fold the names past 20 into the count (`[25, showing first 20]`) - a wide drift on a big ledger used to funnel megabytes of names into one CI log line. The count stays exact and the ledger is where the rest live; cap-shaped battery leg pins both the exact count and the fold-out.

### Fixed (2026-11-01, the v7 prerender seam)

- `web/` moves `react-router-dom` from the v6 line to `^7.18.5` (the advisory fix path the registry audit pointed at keeps the router's own npm audit clean), and the bump exposed a prerender seam the v6 line never hit: react-router-dom 7 resolves its node entry to the CJS `dist/index.js`, which Vite's SSR module registry transforms with an empty exports namespace, and prestruct's engine loads `StaticRouter` by plain dynamic import OUTSIDE that registry - so the naive fixes either lose named exports ("useLocation is not a function") or end up with two module instances minting two React contexts ("useLocation() may be used only in the context of a <Router> component", 0/6 pages rendered). The fix is `web/scripts/rrdom-esm-redirect.mjs`, a load-scoped vite plugin that serves the SSR registry a module delegating to Node's own ESM import of `dist/index.mjs` through a Function-constructed dynamic import - the same file URL the engine's import resolves to, so both sides share one instance and one set of React contexts; `web/vite.config.js` carries `ssr.noExternal` for the registry-in-process path. Client bundle untouched (the vendor manualChunks build is unchanged), `prestruct build` renders 6/6 (the battery's served-dist + prerendered-island legs pass on the rebuilt dist).
- `puppeteer-core` moves from the ^23 line to pinned 25.16.0 per the audit's one-command fix for the nine transitive advisories in its 23.x chain (the extract-zip symlink classes, basic-ftp, zod) - launch API unchanged, battery still 94/0.
